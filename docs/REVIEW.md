# Проверка по официальному ТЗ Career Quest

Проверена реализация кейса Career Quest. Voice Router — отдельный кейс, в этот проект не входит.

| Требование | Реализация / проверка |
|---|---|
| Профиль и карьерная траектория | API профиля и trajectory, экран сотрудника; готовность рассчитывается по требованиям навыков |
| 1–3 шага с обоснованием | Пять факторов скоринга и пять проверяемых объяснений; UI показывает эффект активности |
| История влияет на выбор | Общие навыки, выполненные/пропущенные/отклонённые события, полураспад влияния 180 дней |
| Проверочные профили | Отдельный импорт двух файлов; 3 собственных сложных профиля и тесты ожидаемого выбора |
| Обновление после выполнения | Транзакционная запись в SQLite, пересчёт, соблюдение max_level, защита от повторного зачёта |
| HR: компетенции и выпадение из развития | Графики разрывов, участие, дата последнего завершения, отметка отсутствия завершений 90 дней |
| Права employee/HR | Проверки на сервере, запрет чтения/изменения другого сотрудника, импорт только HR |
| Нет публичного рейтинга | Таблица развития без сортировки по результативности |
| Запуск одной командой | python run.py устанавливает зависимости, собирает фронтенд, запускает приложение |
| UI до 2 с / AI до 10 с | Локальный тест HR на 200 профилях; у LLM ограничение 6 с с fallback. Внешняя задержка зависит от окружения |
| Дополнительные данные | Проверка схемы, ссылок, ID, шкалы 0–5; некорректный импорт не меняет базу |
| Репозиторий и документация | README на английском и русском, lock-файлы, GitHub Actions |

## Исправления при проверке

- Импорт дополнительных профилей теперь сохраняет существующие профили, каталог и завершения.
- Шкала уровней и gain ограничена требованиями официального ТЗ (0–5 и 1–5).
- HR может увидеть отсутствие недавнего развития у конкретного сотрудника.
- Память хранилища обновляется после успешного commit SQLite, а не до него.
- Некорректные формы весов, лишние CSV-поля и ошибочная настройка ключей обрабатываются явно.
- Не-ASCII ввод ключа больше не приводит к внутренней ошибке сервера.
- Браузерные тесты используют отдельную временную базу.
- Официальные данные, локальные секреты и SQLite исключены из публикации.

## Честные границы проверки

Локальная проверка: 32 теста backend проходят, 2 браузерных сценария проходят, production-сборка frontend успешна. Браузерные сценарии проверяют desktop/mobile, полный цикл выполнения и добавление проверочных профилей без замены каталога.

Официальные JSON/CSV и README стартового кита отсутствуют, поэтому совместимость именно с ними пока не проверена. Включены только собственные синтетические примеры. Настоящие три профиля жюри заранее неизвестны; включённые примеры не выдаются за профили организаторов. Реальный API-ключ LLM отсутствует: протестированы управляемые ответы адаптера и fallback. Решение рассчитано на один процесс backend; перед промышленным использованием нужны SSO, аудит и инфраструктурные меры из README.
