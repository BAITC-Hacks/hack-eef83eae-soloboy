# Career Quest — AI-навигатор развития сотрудника

Проект для кейса Career Quest, трек Halyk Bank, HackAlem AI.

Система анализирует профиль, требования следующего грейда и историю участия. Она рекомендует до трёх активностей, объясняет выбор и обновляет навыки после выполнения. HR видит пробелы в компетенциях, участие и сотрудников без завершённых активностей за последние 90 дней.

## Запуск

Нужны Python 3.11+ и Node.js 22.12+. Из корня проекта:

```sh
python run.py
```

Открыть **http://127.0.0.1:8000**. Установка зависимостей и сборка выполняются автоматически. При первом запуске нужен интернет. API-ключ не обязателен.

## Проверка на защите

1. **Try Demo** → выбрать сотрудника → **Open workspace**.
2. Посмотреть навыки, грейд, стаж, готовность к следующему уровню.
3. Раскрыть **Why this recommendation?**: требования грейда, разрыв навыков, история, карьерная ценность и эффект активности.
4. **View Details** → **Complete Activity**. Проверить изменение уровня и обновлённые рекомендации.
5. **Switch workspace / sign out** → **HR workspace**. Посмотреть графики и таблицу развития.
6. **Manage dataset** → **Add jury profiles · 2 files**. Загрузить `employees.json` и `activity_history.csv` с новыми ID. События, навыки и существующий прогресс сохраняются.
7. Для воспроизводимого примера можно добавить два файла из `data/jury-example/`. У `JURY-DESIGN` Public Speaking = 1, System Design = 2; из-за требований грейда и пропусков первым выбирается System Design Workshop.

Режим **Replace all data · 4 files** полностью заменяет набор. В нём нужны `employees.json`, `events.json`, `skills.json`, `activity_history.csv`.

## Что делает AI-слой

Решение принимает прозрачный движок с пятью факторами и настраиваемыми весами: разрыв навыков, важность для грейда, полезность активности, история и карьерная траектория. Пропуски снижают релевантность похожих активностей, но их влияние со временем уменьшается.

LLM через OpenAI-совместимый API выбирает порядок проверенных фактов для объяснения. Он не придумывает рекомендацию и не может подставить произвольные факты. Если API недоступен, используется детерминированное объяснение. Это осознанное ограничение генерации ради достоверности.

## Данные и ограничения

- Официальный стартовый кит в проект не передавался. Файлы в `data/sample` и `data/jury-example` созданы специально для демонстрации и не являются данными организаторов.
- Формат основан на примерах из ТЗ; точную совместимость с неизвестным README стартового кита нельзя подтвердить до получения файлов.
- Уровни навыков: целые 0–5. Рост ограничен `max_level`; повторное выполнение того же события не даёт повторного зачёта.
- В `.gitignore` исключены `.env`, ключи, базы, рабочие файлы и дополнительные каталоги данных. Официальные данные по условиям ТЗ не нужно публиковать на GitHub: храните их локально вне демонстрационных каталогов.
- Демо-режим позволяет выбрать любую роль для защиты. Для конфиденциального внутреннего использования задайте `DEMO_MODE=false` и отдельные ключи доступа либо внедрите SSO.
- Интерфейс пока на английском. Русская и казахская локализация, геймификация и календарь — необязательные расширения.
- Реальный LLM-провайдер без ключа не проверялся: протестированы адаптер, проверка ответа, кеш и отказоустойчивый режим.
